# 股票交易模拟训练平台 - 微信小程序版需求文档

## 1. 项目概述

### 1.1 项目名称
股票交易模拟训练平台（A股） - 微信小程序版

### 1.2 项目目标
开发一个基于微信小程序的A股模拟交易平台。在保留原Web端“随机历史数据训练盘感”的核心功能基础上，增加用户账户体系、多人实时对战（PK）、好友约战及排行榜功能，旨在通过游戏化的方式帮助用户提升投资决策能力。

### 1.3 核心功能
*   **基础训练**：随机获取A股历史K线数据进行模拟交易（单机模式）。
*   **双模式玩法**：支持“日K线操盘”与“分时图操盘”两种模式。
*   **用户体系**：支持微信一键登录，获取头像昵称，使用MySQL持久化存储用户资金、胜率等数据。
*   **多人对战**：
    *   **好友房**：创建房间，分享给微信好友，进入同一房间进行比赛。
    *   **排位赛**：在线快速匹配对手，进行1v1对决。
    *   **对战规则**：同股票、同时间段、20个交易日、初始100万资金，最终资产高者胜。
*   **排行榜**：基于数据库统计的全服盈利/胜率排行榜。

### 1.4 技术栈
| 类别 | 技术选型 |
| :--- | :--- |
| **前端框架** | 微信小程序原生开发 或 Uni-app/Taro (推荐 Uni-app 以便复用逻辑) |
| **图表库** | ECharts for Weixin (ec-canvas) |
| **后端服务** | Node.js / Python / Go (需支持WebSocket以实现实时对战) |
| **数据库** | MySQL (存储用户信息、战绩、排行榜) |
| **缓存/状态** | Redis (可选，用于匹配队列和房间状态) |
| **数据源** | 腾讯/新浪财经API (后端代理转发或前端直接请求) |

## 2. 功能需求详述

### 2.1 账户与数据存储模块 (新特性)
#### 2.1.1 用户登录
*   **游客模式**：不登录也可进行单机基础训练，数据保存在本地缓存（LocalStorage）。
*   **微信登录**：用户授权获取微信昵称和头像。
    *   后端生成唯一User ID，关联OpenID。
    *   初始化数据库记录：默认初始积分/段位。
*   **数据持久化 (MySQL)**：
    *   存储字段：用户ID、昵称、头像URL、当前总资产(模拟币)、排位赛胜场、败场、胜率、历史最高资产等。

#### 2.1.2 排行榜
*   展示全服前100名玩家。
*   维度：总资产榜、排位胜率榜。

### 2.2 游戏模式与玩法 (核心改造)
平台分为两种核心玩法，适用于单机训练和多人对战。

#### 2.2.1 玩法A：日K线操盘 (经典模式)
*   **展示**：仅展示日K线图（蜡烛图）、均线、成交量、副图指标。
*   **操作**：
    *   用户基于当前日K线形态，决定是否买入/卖出。
    *   **交易节点**：按**当日收盘价**进行结算。
    *   点击“下一日”或“买入/卖出”后，K线向后推移一根。

#### 2.2.2 玩法B：分时图操盘 (盘感模式)
*   **展示**：
    *   上方显示日K线图（作为趋势参考，不可操作，仅供查看）。
    *   下方显示**当日分时图**。
*   **动态回放**：
    *   分时图不一次性展示全天数据。
    *   **自动播放**：以 **2秒走完1分钟** 的速度动态绘制分时线。
    *   用户需在分时图跳动过程中寻找买卖点。
*   **操作**：
    *   买入/卖出按分时图当前价格成交。

### 2.3 多人对战模块 (新特性)
#### 2.3.1 房间机制
*   **创建房间 (好友对战)**：
    *   房主设置：玩法选择（日K/分时）。
    *   生成房间号/小程序分享卡片。
    *   通过微信转发分享，好友点击卡片直接加入房间。
*   **快速匹配 (排位赛)**：
    *   系统自动匹配段位/胜率相近的在线玩家。
    *   匹配成功后自动进入对战房间。

#### 2.3.2 对战规则
*   **初始化**：
    *   双方初始资金均为 **1,000,000元**。
    *   系统随机选取一只股票的某段历史时间（例如：2022-01-01 开始）。
    *   双方屏幕显示完全相同的数据。
*   **比赛周期**：
    *   固定为 **20个交易日**。
    *   20个交易日结束后（或分时模式走完20天），比赛强制结束。
*   **胜负判定**：
    *   对比双方最终账户总资产（现金+持仓市值）。
    *   资产高者获胜。
*   **结算**：
    *   更新数据库中的胜败记录。
    *   排位赛模式下更新段位积分。

### 2.4 交易模拟系统 (通用)
*   **买入**：
    *   支持全仓、半仓、1/3仓、自定义股数。
    *   校验资金是否充足，遵循A股一手(100股)规则。
*   **卖出**：
    *   支持全卖、半卖。
    *   遵循T+1规则（当日买入次日可卖，分时模式下需特别注意T+1限制，即当日买入后，分时图走完当日才可卖出，或次日分时图开始时可卖）。
*   **费用**：
    *   模拟佣金万分之三，印花税千分之一（卖出收）。

### 2.5 图表展示模块
*   **适配移动端**：
    *   ECharts 需针对小程序优化触摸手势（双指缩放、长按查价）。
    *   竖屏布局：上部K线/分时，中部操作盘，底部资产信息。
*   **技术指标**：
    *   主图：MA5, MA10, MA20。
    *   副图：VOL, MACD, KDJ。

## 3. 页面布局与交互设计

### 3.1 页面规划
1.  **首页**：
    *   用户信息区（头像、昵称、战绩）。
    *   功能入口：单机训练、排位匹配、创建房间、排行榜。
2.  **单机训练页**：
    *   模式选择弹窗（日K/分时）。
    *   交易主界面。
3.  **对战房间页 (等待中)**：
    *   显示房主与挑战者头像。
    *   “准备”与“开始”按钮。
4.  **对战进行页**：
    *   顶部：双方资产对比条（实时显示我方vs敌方资产进度）。
    *   中部：图表区。
    *   底部：交易操作区。
5.  **结算页**：
    *   胜负动画（胜利/惜败）。
    *   双方收益曲线对比图。
    *   “再来一局”或“分享战绩”。

### 3.2 微信特性交互
*   **分享**：生成带战绩的精美海报或小程序卡片。
*   **震动反馈**：买卖成交时触发手机震动（Taptic Engine）。

## 4. 数据库设计 (MySQL)

### 4.1 用户表 (users)
| 字段名 | 类型 | 说明 |
| :--- | :--- | :--- |
| id | BIGINT | 主键 |
| openid | VARCHAR | 微信OpenID |
| nickname | VARCHAR | 昵称 |
| avatar_url | VARCHAR | 头像链接 |
| total_assets | DECIMAL | 当前模拟总资产 (默认100万起，随排位变动或仅记录最高记录) |
| win_count | INT | 胜场 |
| lose_count | INT | 败场 |
| created_at | DATETIME | 注册时间 |

### 4.2 对战记录表 (battle_records)
| 字段名 | 类型 | 说明 |
| :--- | :--- | :--- |
| id | BIGINT | 主键 |
| room_id | VARCHAR | 房间号 |
| player1_id | BIGINT | 玩家1 ID |
| player2_id | BIGINT | 玩家2 ID |
| stock_code | VARCHAR | 比赛股票代码 |
| start_date | DATE | 比赛历史起始日期 |
| winner_id | BIGINT | 获胜者ID |
| created_at | DATETIME | 比赛时间 |

## 5. 非功能需求

### 5.1 性能要求
*   **分时图渲染**：在“2秒1分钟”的高频刷新下，小程序Canvas不得卡顿、闪退。
*   **网络延迟**：对战模式下，双方数据同步误差需控制在500ms以内（依赖WebSocket）。

### 5.2 兼容性
*   适配 iPhone X 及以上刘海屏/灵动岛机型。
*   适配 Android 主流机型。

### 5.3 开发阶段规划
1.  **P0**: 完成小程序基础框架搭建，移植ECharts图表，实现单机版日K/分时玩法。
2.  **P1**: 接入微信登录，搭建MySQL数据库，实现用户数据存取。
3.  **P2**: 开发WebSocket服务，实现房间创建、加入、同步开始功能。
4.  **P3**: 完善排位匹配机制与排行榜，UI精修。
